# originality-reviewer — 原创性审查

## 职责

对原创故事（设定、人物、大纲、章节）进行原创性风险筛查，输出改进建议。

## 定位声明

本 Skill 是**创作阶段风险筛查工具，不是法律判定工具**。输出不构成法律意见。

## 前置条件

1. 读取 `00_system/COPYRIGHT_RULES.md`（GREEN/YELLOW/RED 分层）。
2. 读取 `03_story_dna/master/` 或相关区域的机制库（如已建立）。
3. 读取待审原创材料（`04_original_project/`）。

## 审查清单（逐项检查）

1. **一一对应人物**：是否存在与某参考作品角色在（身份+欲望+关系位置+功能）四维上同时对应的角色？
2. **独特世界设定**：是否复制了某作品的专有世界观名词或高度独创的规则体系？
3. **连续剧情节点**：是否存在 3 个以上连续剧情节点与某作品同构且顺序一致？
4. **标志性场景**：是否复刻了某作品的标志性场景（视觉桥段、名场面）？
5. **改名换皮**：是否只是人物改名/换性别/换职业，其余照搬？
6. **组合指向性**：多个非独创元素组合后，是否仍高度指向某部原著（组合识别度）？
7. **可抽象空间**：是否存在可以进一步抽象、重组、原创化的部分？

## 评级

每项检查输出：
- `PASS`：安全
- `CAUTION`（对应 YELLOW）：有识别度，建议变形（给出具体变形方向：改变组合顺序/题材载体/人物配置/情绪基调中至少 2–3 项）
- `FAIL`（对应 RED）：直接对应原著独有表达，必须重做

## 输出格式

```
05_originality_review/<项目名>/<日期>_review.md
```

包含：
- 逐项检查结果与证据（指向原创材料的具体位置）
- 总体风险评级
- 修改建议（不是替作者重写，而是指出变形方向）
- 建议保留的 GREEN 机制（明确这些抽象机制可放心使用）

## 原则

- 审查的目的是**扩大创作自由**（明确什么可以放心用），不只是限制。
- 对 GREEN 机制要明确说"可用"，避免创作者过度自我审查。
- 结论必须给出依据，不做凭空指控。
